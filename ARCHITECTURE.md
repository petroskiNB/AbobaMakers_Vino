# Архитектура

## Компоненты

| Компонент | Реализация |
|---|---|
| Интерфейс | Статические HTML/CSS/JavaScript в `web/`, без Nuxt и сборщика |
| API | FastAPI, `wine_ml/api.py` |
| Визуальная модель | SigLIP2 и остаточный адаптер, `core.py` |
| Визуальный поиск | `predict.py`, матрица нормализованных признаков |
| Текстовый поиск | RapidOCR и символьные n-граммы, `ocr.py` |
| Объединение | Weighted reciprocal-rank fusion, `hybrid.py` |
| Сомелье | YandexGPT в `sommelier.py` либо правила в `pairing.py` |
| Обучение | `experiment.py` и скрипты в `scripts/` |

## Путь фотографии

```text
Браузер → POST /v1/predict → проверка и декодирование
  ├─ четыре представления → SigLIP2 → адаптер → визуальный поиск
  └─ центральный кроп → RapidOCR → текстовое ранжирование
  → объединение рангов → статус → карточка и кандидаты
```

API ограничивает размер файла, исправляет EXIF-ориентацию и обрабатывает прозрачность. Визуальный поиск берёт максимальное сходство по четырём представлениям запроса и двум представлениям каждого эталона. Энкодер заморожен; обучался адаптер.

При старте загружаются и проверяются согласованные артефакты, затем выполняется прогрев. При наличии `ocr_index.json` выбирается HybridRecognizer, иначе Recognizer. Каталог хранится в JSON, индекс — в файле PyTorch; отдельной СУБД нет.

Гибрид использует до 60 кандидатов каждого метода и RRF с константой 60. Вес OCR читается из `hybrid_metrics.json`, без файла равен 0,45. Сохранённый эксперимент выбрал 0, однако OCR продолжает выполняться и участвует в определении статуса.

Статус `found_candidate` требует попадания победителя в первые десять результатов обоих методов. Визуальный порог при этом не проверяется. Статус не является подтверждённой вероятностью правильного распознавания. Пустой OCR пока не исключает кандидатов с нулевым совпадением.

## API и интерфейс

`/v1/eval/predict` возвращает ближайший slug; `/v1/predict` — карточку, статус и альтернативы. Первый результат открыт сразу, остальные скрыты в раскрываемом списке. При выборе альтернативы меняется slug для сомелье и сбрасывается старая рекомендация.

Вызовы распознавания выполняются под блокировкой в пределах процесса. Docker использует один worker, чтобы не дублировать модель. `latency_ms` гибридного ответа складывает время визуального поиска и OCR; передача файла и очередь в него не входят.

## Сомелье

`/v1/pairing` получает slug и dish, выбирает карточку из каталога и вызывает настроенного провайдера. YandexGPT получает текст блюда и доступные поля карточки. Pydantic проверяет ответ; при недостаточной информации допустим уточняющий вопрос без оценки.

Ключ читается из окружения или `.env`; окружение приоритетно. Он не передаётся браузеру. Ошибки внешнего сервиса возвращаются без ключа. Автоматического fallback, кэша рекомендаций и ограничения расходов пока нет. Число 0–100 обозначает условную гастрономическую совместимость.

## PWA и инфраструктура

FastAPI раздаёт `web/`. Service worker кэширует оболочку интерфейса, но не API-запросы и фотографии. Без сети распознавание и рекомендации недоступны.

Nginx завершает HTTPS и направляет запросы на локальный порт контейнера. Docker-образ включает код и зависимости, артефакты подключаются только для чтения, секреты передаются отдельно. `WINE_PREVIEW=1` включает интерфейс без модели.

## Границы реализации

SIFT/RANSAC в `local_features.py` и `check_geometry.py` — отдельная диагностика, не часть рабочего API. Рейтинг Роскачества, история и избранное отсутствуют.

Метки каталога предварительные. Оценка обучения синтетическая, а калибровка отличается от процесса обработки API. Надёжный отказ для неизвестных вин требует отдельной размеченной проверки. Подробности — в [результатах обучения](docs/TRAINING_RESULTS.md).
