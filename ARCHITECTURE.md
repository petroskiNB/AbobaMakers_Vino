# Архитектура распознавания вина (проект)

Реализованы аудит `scripts/prepare_catalog.py`, энкодер и адаптер `wine_ml/core.py`, эксперимент `wine_ml/experiment.py`, визуальный поиск `wine_ml/predict.py`, OCR `wine_ml/ocr.py`, гибрид `wine_ml/hybrid.py`, локальный API `wine_ml/api.py` и интерфейс в `web/`. Результаты фактического запуска хранятся в `artifacts/experiment/`.

```text
Фотография → ориентация/фон → несколько центральных представлений
    ├→ SigLIP 2 + адаптер → визуальный поиск по двум видам эталона
    └→ OCR → поиск по тексту этикетки и полям карточки
    → reciprocal-rank fusion → объединение по slug
    → проверка уверенности → карточка или не найдено/переснять
```

Каталог хранит slug, атрибуты карточки и проверенные ссылки на изображения. Манифест происхождения отделяет оригиналы от миниатюр. Обучение использует отдельные размеченные выборки, а построение индекса — каталог эталонов. Параметры модели и индекс версионируются совместно.

Python-сервис загружает модель и индекс при старте, прогревается и обслуживает запросы без скачивания весов. Для небольшого каталога достаточно матрицы нормализованных признаков и точного косинусного поиска. pgvector можно подключить через отдельный адаптер хранения при интеграции с PostgreSQL.

Адаптер оценки `/v1/eval/predict` принимает multipart-поле `image` и возвращает плоский JSON `{"slug":"..."}`. Контракт сверён с предоставленным скриптом. API `/v1/predict` отдельно возвращает статус, карточку, оценки сходства и диагностические кандидаты. Оценки сходства не называются F1 или вероятностью. Пока отказ не калиброван, возвращается статус `uncalibrated_candidate`; endpoint оценки принудительно отдаёт ближайший slug. Каталог первого эксперимента неполный: сомнительные ссылки исключены, поэтому отсутствующие в индексе вина распознать точно невозможно.

Nuxt отвечает за мобильную загрузку фото и карточку. Дополнительная функция: подбор блюда по доступным атрибутам и сохранение впечатления. Рейтинг, цена и наличие показываются только при наличии соответствующих данных; генерация текста не создаёт эти факты.

SIFT/RANSAC реализован как отдельный диагностический эксперимент `wine_ml/local_features.py`, но не подключён к API: совпадение общих рисунков похожих серий не обеспечило различение надписей на публичных фото. Мобильный интерфейс реализован без сборщика как статическая страница, которую отдаёт FastAPI. Дополнительная функция подбирает базовую гастрономическую рекомендацию по категории и сорту; это правило, а не LLM и не экспертная оценка конкретного блюда.
