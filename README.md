# AbobaMakers_Vino

Сканер российских вин для кейса РСХБ.Цифра.

План и объяснение обучения: [docs/PLAN_RU.md](docs/PLAN_RU.md).
Границы компонентов: [ARCHITECTURE.md](ARCHITECTURE.md).
Фактические результаты: [docs/TRAINING_RESULTS.md](docs/TRAINING_RESULTS.md).

## Текущее состояние

Реализованы аудит каталога, извлечение признаков SigLIP 2, обучение остаточного адаптера, OCR-поиск, гибридное ранжирование, локальный API и мобильная веб-страница. Данные: `data/foto`, `data/strapi_output0709.csv`, `data/eval`. Результаты обучения фиксируются в `artifacts/experiment/metrics.json`, расширенные метрики — в `calibration.json` и `hybrid_metrics.json`.

Обучение завершено: 1970 вин в индексе, 15 эпох, выбрана эпоха 13. Синтетический test Accuracy@1: 90.78% → 93.17%. На реальных публичных фото обнаружены несоответствия; эти синтетические метрики нельзя выдавать за точность в магазине.

Это исследовательский прототип: связи по именам предварительные, каталог поиска сокращён до неконфликтующих кандидатов, проверка обучения синтетическая. OCR и мобильный интерфейс реализованы. Отказ откалиброван только для известных вин; полноценная калибровка неизвестных требует размеченных отрицательных фото.

## Аудит

Python 3.10+, сторонние зависимости не нужны. Команды из корня репозитория:

```powershell
python scripts/prepare_catalog.py --images data/foto
python scripts/prepare_catalog.py --images data/foto --catalog data/strapi_output0709.csv
```

Вторая команда требует реального CSV с колонками `Slug` и `Название фото` в UTF-8. Скрипт не изменяет исходные данные. Результаты: `artifacts/data_audit/report.json`, `inventory.csv`, а при наличии каталога — `candidate_links.json` и `content_conflicts.json`. Все связи требуют проверки; статус `candidate` не означает подтверждённую разметку.

## Установка и обучение (Windows, Python 3.12)

```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install torch==2.11.0 torchvision==0.26.0 --index-url https://download.pytorch.org/whl/cu128 --timeout 180
.venv/Scripts/python.exe -m pip install -r requirements.lock.txt --timeout 180
.venv/Scripts/python.exe -X utf8 scripts/download_model.py
.venv/Scripts/python.exe -X utf8 scripts/prepare_catalog.py --images data/foto --catalog data/strapi_output0709.csv
.venv/Scripts/python.exe -X utf8 -m wine_ml.experiment extract
.venv/Scripts/python.exe -X utf8 -m wine_ml.experiment train --epochs 15
.venv/Scripts/python.exe -X utf8 scripts/calibrate.py
.venv/Scripts/python.exe -X utf8 -m wine_ml.ocr
.venv/Scripts/python.exe -X utf8 scripts/evaluate_hybrid.py
```

Загрузка зависимостей и официальных весов требует интернета и нескольких гигабайт свободного места. После скачивания энкодер загружается только из `artifacts/base_model`; при распознавании сетевые запросы не выполняются. Переменные окружения и ключи API не требуются. Команды выполняются из корня проекта.

В `artifacts/experiment`: `manifest.json` и `excluded.json` (состав выборки), `features.pt`, `adapter_last.pt` (реально обученные веса последней эпохи), `adapter_best.pt` (выбор по validation, возможно исходное преобразование), `index.pt`, `metrics.json`. При изменении энкодера, обработки фото или каталога признаки и индекс нужно пересоздать.

## Запуск и проверка

### Установка PWA

Сайт поддерживает установку как PWA: название и иконки, отдельное окно, кэш интерфейса после первого успешного открытия. Фотографии, ответы API и состояние модели не кэшируются. Без сети можно открыть интерфейс и выбрать фото; распознавание и рекомендации требуют доступного сервера с моделью.

Для локальной проверки на компьютере:

```powershell
.\scripts\run.ps1 -Preview -Port 8081
```

Откройте `http://127.0.0.1:8081/` в Chrome или Edge. Если браузер разрешает установку, появится кнопка «Установить»; также используйте пункт установки в меню браузера. Встроенный браузер среды разработки может не поддерживать установку.

Для установки на телефон нужен доступный телефону **HTTPS-адрес** этого же приложения (доверенный сертификат, например через HTTPS reverse proxy). На Android используйте кнопку установки или меню браузера, на iPhone — «Поделиться» → «На экран Домой». Настройка внешнего HTTPS-размещения в проект не входит. `127.0.0.1` на телефоне указывает на сам телефон, а не на компьютер.

Для проверки только веб-версии по домашней Wi-Fi сети можно запустить `scripts/run.ps1 -Preview -Port 8081 -BindAddress 0.0.0.0` и открыть `http://<IPv4 компьютера>:8081/` с телефона. Компьютер и телефон должны быть в одной сети, а брандмауэр — разрешать подключение. Обычный HTTP по LAN-IP не обеспечивает установку PWA и работу service worker. По умолчанию сервер доступен только на компьютере.

Проверка офлайн: откройте страницу онлайн, дождитесь установки service worker, затем остановите сервер и обновите страницу — интерфейс должен открыться, а распознавание остаться недоступным. После запуска сервера нажмите «Проверить подключение».

После изменений файлов интерфейса увеличивайте версию `CACHE_NAME` в `web/sw.js`. Новая версия кэша готовится целиком; ожидающий service worker активируется после закрытия старых вкладок приложения и повторного открытия.

### Обычный запуск

Для проверки интерфейса без фотографий и весов модели:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-web.txt
.\scripts\run.ps1 -Preview
```

Откройте `http://127.0.0.1:8080/`. В режиме просмотра можно выбрать фото и проверить интерфейс; распознавание и рекомендации возвращают HTTP 503 с объяснением, а `/health` сообщает `ready: false`. Активация `.venv` не требуется, путь к Python вычисляется относительно скрипта.

Для полноценного распознавания установите ML-зависимости по инструкции выше и восстановите обученные артефакты (`artifacts/base_model` и `artifacts/experiment`, включая `index.pt` и `adapter_best.pt`) либо выполните обучение после добавления данных. Одного копирования фотографий в `data` недостаточно. Обычный запуск:

```powershell
.\scripts\run.ps1
```

В другом терминале:

```powershell
.venv/Scripts/python.exe -X utf8 scripts/evaluate_public.py
.venv/Scripts/python.exe -X utf8 -m wine_ml.predict data/eval/queries/019c68d0.jpg
.venv/Scripts/python.exe -X utf8 -m unittest discover -s tests
```

Откройте `http://127.0.0.1:8080/`. `GET /health` — готовность и размер каталога. `POST /v1/eval/predict` — поле `image`, ответ `{"slug":"..."}`. `POST /v1/predict` — карточка, OCR и диагностические кандидаты. `POST /v1/pairing` — рекомендация к блюду. Оценочный endpoint всегда возвращает ближайший slug для совместимости; продуктовый API умеет вернуть `low_confidence_reshoot`.

`scripts/evaluate_public.py` — собственный последовательный HTTP-прогон для Windows с полями JSONL из скрипта организатора; он не подменяет официальный Bash-скрипт. Существующий файл результатов не перезаписывается: задайте другой `--output` для повторного прогона. Публичные ответы закрыты, поэтому точность по этим трём фото не рассчитывается.

Отдельная диагностическая проверка локальных деталей (не используется основным API):

```powershell
.venv/Scripts/python.exe -X utf8 -m wine_ml.local_features
.venv/Scripts/python.exe -X utf8 -m wine_ml.check_geometry
```

Она сохраняет `local_features.npz` и `artifacts/geometry_ablation.json`. На просмотренных публичных фото геометрия не решила путаницу похожих серий; увеличение числа совпавших элементов оформления не доказывает совпадение вина.

### Подбор блюда

`POST /v1/pairing` принимает `slug` вина и `dish` (1–300 символов). Это локальный API: внешние LLM и платные сервисы не используются. Модуль `wine_ml/pairing.py` определяет продукт по словарю, стиль и явно указанную сладость вина по карточке, затем учитывает соус, остроту, жарку/гриль. Ответ содержит `score`, `label`, `reasons`, `recommendations`, `recognized_foods`, `method` и `disclaimer`; прежнее поле `explanation` сохранено.

Шкала 0–100 — авторская эвристика (`rules-v1`), не вероятность, не F1 и не дегустационная оценка. Матрица баллов не обучена и не валидирована экспертами. Для неизвестного блюда, неизвестного стиля вина или десерта без данных о сладости возвращается `score: null` и просьба уточнить данные. Словарь не является полноценным пониманием языка: сложные рецепты, отрицания и опечатки могут разбираться неточно. Рекомендация относится к найденной карточке, а не подтверждает корректность распознавания вина.

Гастрономические принципы: [WSET — Food and wine pairing](https://www.wsetglobal.com/knowledge-centre/blog/2023/july/13/four-rules-to-masterful-food-and-wine-pairing), [WSET — pairing drinks with spice](https://www.wsetglobal.com/knowledge-centre/blog/2026/how-to-pair-drinks-with-spice). Численные баллы задаются в коде проекта, а не взяты из WSET.

### YandexGPT для рекомендаций

Скопируйте `.env.example` в `.env`, если файла ещё нет. Заполните `YANDEX_API_KEY` (секретное значение, не ID ключа) и `YANDEX_FOLDER_ID`. Модель по умолчанию — `yandexgpt/rc`; можно задать другой поддерживаемый идентификатор в `YANDEX_MODEL`. `PAIRING_PROVIDER=yandex` включает внешний API, `rules` явно включает прежние локальные правила. Файл `.env` исключён из Git; переменные окружения имеют приоритет. Настройки читаются при запросе — после изменения ключа перезапуск не нужен.

Сервер обращается к `https://ai.api.cloud.yandex.net/v1/chat/completions`. Наружу передаются текст блюда и выбранные поля карточки, фотография не передаётся. Запросы оплачиваются по тарифу провайдера. Ключ не передаётся браузеру. При отсутствии настроек или ошибке API выводится понятное сообщение, скрытого перехода к ручным баллам нет. Для уточнения дополните описание в поле блюда и отправьте снова; отдельная история диалога не хранится.

Ответ проверяется через Pydantic. Неполный JSON, незавершённая генерация и некорректные оценки отклоняются. Оценка ИИ не валидирована экспертами; внешняя модель не подтверждает результат распознавания. Перед публичным размещением добавьте аутентификацию и лимиты вызовов, поскольку сейчас любой посетитель сервиса может инициировать оплачиваемый запрос.

Документация провайдера: https://aistudio.yandex.ru/ru/docs/ai-studio/operations/generation/completions-structured
