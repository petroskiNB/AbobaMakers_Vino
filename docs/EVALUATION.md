# Оценка и живое демо

Публичный комплект `data/README.md` прямо указывает: правильные ответы доступны
только организаторам. Нельзя заменять их предсказаниями самой модели. Без разметки
показываются задержка, ответы и HTTP-успех, а показатели качества остаются null.

## Прогон на компьютере команды

Страница живого прогона: `/static/evaluation.html` на локальном API или
https://abobawines.ru/static/evaluation.html на сервере. Выберите манифест,
фотографии и, если есть, независимо составленную разметку команды. Страница
показывает micro-F1 для top1/top5, Accuracy, Recall@5, задержки и экспорт JSON.
Без разметки доступны только ответы и скорость. Серверный прогон не заменяет
требуемое живое демо на компьютере команды.

Сохранённый синтетический тест пересчитывается командой
`.\.venv\Scripts\python.exe scripts/evaluate_saved_features.py`.
Результат записывается в `web/synthetic-evaluation.json`.

Запустите модель в одном PowerShell:

```powershell
.\scripts\run.ps1 -Port 8080
```

Во втором терминале выполните (каталог результатов должен быть новым):

```powershell
.\.venv\Scripts\python.exe scripts/live_evaluation.py --output-dir artifacts/demo-run-01
```

Пути по умолчанию: `data/queries.tsv`, `data/queries`. Для другого набора задайте
`--manifest` и `--images-dir`. Для внешнего сайта добавьте
`--endpoint https://abobawines.ru/v1/predict`.

Терминал после каждого фото показывает топ-1, топ-5, время HTTP-запроса и
накопленные метрики. Сохраняются `predictions.jsonl` и `summary.json`, хеши фото,
манифеста и разметки. Ошибки не исключаются. Время включает передачу и очередь;
автоматических повторов и исключения первого запроса нет. API сам прогревается
при старте. Порог считается строго: успешный запрос быстрее 3000 мс.

## Разметка и формулы

Независимый TSV должен содержать заголовки `query_id` и `expected_slug`, разделённые
табуляцией, и ровно один подтверждённый slug для каждого запроса. Передайте его
через `--labels путь/labels.tsv`. Разметка не передаётся сервису распознавания.
Нельзя заполнять её ближайшими предсказаниями. Текущий формат предполагает одно
известное вино на фото; проверка неизвестных/шума требует отдельного протокола.

- Accuracy@1: доля правильных первых ответов, включая ошибки запросов в знаменателе.
- Macro-F1 top1: среднее F1 по объединению истинных и предсказанных классов.
- Micro set-F1@1: 2 × правильные первые ответы / (число первых ответов + число запросов).
- Recall@5: доля запросов с правильным slug среди пяти кандидатов.
- Micro set-F1@5: 2 × число попаданий / (число возвращённых кандидатов + число запросов).

Последняя формула рассматривает пятёрку как множество предсказаний. При пяти
кандидатах и одном правильном ответе даже идеальный Recall@5 даёт F1=1/3.
Это не Recall@5 и не согласованная с организаторами формула «F1 для топ-5»:
до защиты необходимо уточнить их определение. Синтетические показатели из
calibration.json нельзя выдавать за качество публичного набора.

## Контрольный скрипт кейсодержателя

Оригинал `data/participant_test.sh` оставлен без изменений. На Linux с bash,
curl, jq и awk выполните:

```bash
bash data/participant_test.sh --images-dir data/queries --manifest data/queries.tsv --endpoint http://127.0.0.1:8080/v1/eval/predict --output artifacts/organizer-public-01.jsonl
```

Для Windows можно использовать WSL с установленными утилитами и доступным из
WSL адресом API (localhost зависит от режима сети WSL). Проверьте доступность
`/health` из той же среды заранее. Во время звонка используйте выданные
организатором пути приватного набора и новый выходной файл. Этот скрипт сохраняет
только top1 и задержки, не вычисляет F1 и не сохраняет top5.

## Сценарий демонстрации до 7 минут

0:00–0:45 — показать готовность локального API и размер индекса.
0:45–2:30 — загрузить реальное фото в интерфейс, показать карточку и кандидатов.
2:30–4:30 — выполнить live_evaluation.py; показать скорость и при наличии
независимой разметки метрики top1/top5, пояснив формулы.
4:30–6:15 — выполнить неизменённый скрипт организаторов и показать JSONL.
6:15–7:00 — обозначить ограничения и завершить. Запись выполняется непрерывно.

Наличие инструментов не гарантирует качество 90–100% и SLA. Эти требования
подтверждаются результатами на согласованном наборе. Приватный контрольный прогон
выполняется на звонке после получения данных, его нельзя считать завершённым заранее.
